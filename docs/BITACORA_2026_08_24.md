# Bitácora de Desarrollo - 24 de Agosto de 2026

## Cambios y Optimizaciones Implementadas

### 1. Refactorización Nutricional (Módulo de Recetas)
- Se actualizó el esquema y la lógica para manejar grupos nutricionales ampliados (matriz de 5 edades x 6 nutrientes principales).
- Se crearon migraciones para incluir los campos faltantes en `recipe_nutrition` (`total_calcium`, `total_iron`, `total_sodium`).
- Se reescribió la lógica del cálculo nutricional en `RecipeController::recalculateNutrition` para computar dinámicamente los porcentajes de aporte sobre la nueva tabla dinámica 5x6.
- Actualización de la interfaz en `recetario.js` para renderizar el resumen nutricional con el nuevo formato.

### 2. Optimización de Rendimiento Extremo (Módulo de Beneficiarios)
- Se detectó un cuello de botella por la carga de más de 25,000 registros completos en memoria (Client-Side rendering).
- **Server-Side Processing**: Se migró el DataTables de `beneficiaries.js` para consumir datos paginados directamente desde el servidor.
- Creación de dos nuevos endpoints en la API: `POST /api/beneficiarios/datatable` para paginación/búsqueda rápida y `GET /api/beneficiarios/{id}` para edición y generación de carnets.
- Ajuste de diseño de columnas CSS para asegurar que los botones de acción sean 100% visibles al deshabilitar el cálculo dinámico (`autoWidth: false`).

### 3. Carga Masiva (BeneficiaryImportController)
- Se aseguró que los estudiantes recién importados se establezcan como `'ACTIVO'` en la base de datos (campo `status`).
- Se agregó una actualización (`ON DUPLICATE KEY UPDATE`) para que los alumnos que ya existían pero que estaban en otros estados ('INACTIVO', 'DESERTADO') vuelvan a quedar activos automáticamente al ser incluidos en la nueva carga masiva del archivo.
- Se implementó parseo dinámico de fechas y se incluyó por defecto el check de Hábeas Data en 1 (Autorización concedida).
